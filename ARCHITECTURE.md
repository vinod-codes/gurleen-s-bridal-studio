# Architecture & Continuation Guide

## Overview

**GKP Artistry & Makeovers** is a luxury bridal makeup and professional makeup academy website built with modern web technologies. This document serves as a comprehensive onboarding guide for developers continuing work on this project.

### Tech Stack
- **Framework:** React 19 + Vite
- **Routing & SSR:** TanStack Start & TanStack React Router
- **Styling:** Tailwind CSS v4 + Class Variance Authority (`cva`) + `clsx`/`tailwind-merge` (`cn` utility)
- **UI Components:** Radix UI primitives (accessible, unstyled components) + custom components (like shadcn/ui)
- **Animations:** Framer Motion, GSAP, and OGL (WebGL)
- **Forms & Validation:** React Hook Form + Zod
- **Icons:** Lucide React

---

## High-Level Flow & System Behavior

The application is structured around a file-based routing system (`TanStack Router`). The entry points are separated for client and server to support Server-Side Rendering (SSR).

1. **Routing Shell (`src/routes/__root.tsx` & `src/router.tsx`)**
   The application shell defines the root layout, global error handling, and integrates global components like `Nav`, `Footer`, and `FloatingWhatsApp`.
   - `FileRoutesByPath` is automatically generated by TanStack Router based on the `src/routes/` directory.

2. **Core Abstractions & God Nodes (Graphify Insights)**
   - `cn()`: The most heavily used utility for merging Tailwind classes safely.
   - `Nav()` & `Footer()`: Global layout components present on almost every page.
   - `Reveal()`: A wrapper component used widely for scroll-based or entrance animations.
   - `FloatingWhatsApp()` & `wa()`: Global components/utilities for WhatsApp integration and inquiries.

## Step-by-Step Breakdown of Key Parts

### 1. Project Structure
- `src/components/ui/`: Contains all primitive UI components built on top of Radix UI (e.g., `dialog.tsx`, `sheet.tsx`, `tabs.tsx`). These form the core design system.
- `src/routes/`: Contains all the page routes. Subdirectories like `academy/` contain nested routes for specific services.
- `src/lib/` or `src/utils/`: Contains utility functions like the `cn()` class merger.

### 2. Styling & Theming
The project uses Tailwind CSS v4. Design tokens for the luxury brand (Ivory, Ink, Wine, Gold, Taupe, Sand) are integrated here. Ensure you use these semantic colors instead of generic Tailwind colors to maintain brand consistency.

### 3. Navigation & Layout Community
According to the Graphify analysis, layout and navigation components form a major community. 
- **Dependencies:** The navigation relies heavily on `Nav()`, `NavigationMenu`, and `Sheet` (for mobile menus).
- **Pitfall:** Ensure mobile responsive navigation (`Sheet` component) is updated alongside desktop navigation (`NavigationMenu`).

### 4. Interactive Components & Forms
- The project relies on **React Hook Form** with **Zod** resolvers for validation.
- The `Form` community (`form.tsx`, `Input`, `Checkbox`, `RadioGroup`) is highly cohesive. Always use the provided `FormItem`, `FormLabel`, and `FormControl` wrappers to ensure accessibility (aria-attributes) and consistent error messaging.

## Pitfalls & Edge Cases

1. **SSR Hydration Mismatches:**
   Since this uses TanStack Start for SSR, be careful with browser-only APIs (`window`, `localStorage`). Use `useEffect` or check `typeof window !== 'undefined'` before accessing them.

2. **Animation Performance:**
   The project uses GSAP, Framer Motion, and OGL. Mixing these can lead to performance bottlenecks or conflicting DOM manipulations. 
   - *Tip:* Stick to Framer Motion for simple UI transitions (like `Reveal()`) and OGL/GSAP only for complex canvas/scroll-hijacking effects.
   - *Accessibility:* Respect `prefers-reduced-motion` settings.

3. **Graphify Isolated Nodes:**
   The graph analysis identified around 400 isolated nodes (like `$schema`, `style`, `rsc`, `css`). This indicates that many CSS files or config schemas are not explicitly imported in a way the static analyzer catches, or they are global. Ensure you don't accidentally delete CSS files assuming they are unused.

4. **Routing Dependencies:**
   Avoid circular dependencies in routes. The router is strictly configured via `src/router.tsx`. If adding new routes, rely on the file-based generation plugin rather than manual route definitions.

## Suggested Next Steps for New Developers

1. **Local Setup:**
   Run `npm install` (or `bun install` as `bun.lock` is present) and `npm run dev` to start the Vite server.
2. **Review the UI Library:**
   Familiarize yourself with the components in `src/components/ui/`. They are the building blocks for any new feature.
3. **Check Routing Configuration:**
   Look at `src/routes/__root.tsx` to understand the global layout and data fetching strategies.
4. **Graphify Maintenance:**
   Run `graphify update .` whenever you make significant structural changes to keep the `graphify-out/` knowledge graph fresh.
